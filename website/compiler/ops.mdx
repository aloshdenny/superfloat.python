Each op lists its operands, attributes, result, shape rule, exact semantics on integer codes, events, memory effects, faults, predication, the v1 hardware unit, a suggested MLIR op with traits, and the rewrites that are and are not legal. Ops with golden vectors say so.

## SF arithmetic

### add

`%r:sfN = add %a, %b` · version 1.0

| | |
|---|---|
| Operands | a: sfN, b: sfN (same N) |
| Result | sfN |
| Shape | numpy broadcast of the operand shapes (rank &lt;= 3); scalars are shape () |
| Semantics | s = a + b (exact integer). If \|s\| > M: result = sign(s)*M, overflow. Else result = s. |
| Events | overflow |
| Memory | none |
| Predication | events |
| Hardware | ACT unit (add) |
| v4.8.1 | **native**: ACT f=00 Rd, Ra, Rb with Rd in &#123;R0, R4, R8, R12&#125;. Not integer ADD, which is wrong for negative sign-magnitude values (ISA s3.2) |
| v4.8.1 cost | 1 instruction |
| MLIR | sf.add; traits: EventEffect (not Pure), Commutative, Elementwise, SameOperandsAndResultType |
| From Python | a + b |
| Golden vectors | `spec/golden/add.json` |

**Rewrites:**

- commutative: a+b = b+a (legal)
- NOT associative: (a+b)+c != a+(b+c) when an intermediate saturates. Do not reassociate, do not reorder a chain, do not tree-reduce.
- x + 0 -> x (legal)
- never turn a+a into 2*a via mul (mul cannot represent 2)

**Notes:**

- sfN &lt; 16 on the sf16 datapath: shift left by 16-N, add, saturate at the sfN max shifted, shift back. The saturation threshold must be sfN's M, not sf16's.

### mul

`%r:sfN = mul %a, %b` · version 1.0

| | |
|---|---|
| Operands | a: sfN, b: sfN |
| Result | sfN |
| Shape | numpy broadcast of the operand shapes (rank &lt;= 3); scalars are shape () |
| Semantics | p = a * b (exact, up to 2(N-1)+1 bits). result = trunc_toward_zero(p / 2^(N-1)). underflow if p != 0 and result == 0. \|result\| &lt; M always, so mul never overflows. |
| Events | underflow |
| Memory | none |
| Predication | events |
| Hardware | FMA unit (c = 0) |
| v4.8.1 | **native**: FMA with Rd = +0: CONST Rd, 0 (or copy Z), then FMA Rd, Ra, Rb. Truncates toward zero (ISA s5) |
| v4.8.1 cost | 2 instructions |
| MLIR | sf.mul; traits: EventEffect (not Pure), Commutative, Elementwise, SameOperandsAndResultType |
| From Python | a * b |
| Golden vectors | `spec/golden/mul.json` |

**Rewrites:**

- commutative (legal)
- NOT associative: truncation after each product
- NOT distributive over add
- x * 0 -> 0 (legal, no event)
- there is no 1.0, so there is no multiplicative identity to fold

**Notes:**

- truncation is toward zero, NOT floor: an arithmetic right shift on a negative product is wrong. Shift the magnitude, then reapply the sign.

### div

`%r:sfN = div %a, %b` · version 1.0

| | |
|---|---|
| Operands | a: sfN (dividend), b: sfN (divisor) |
| Result | sfN |
| Shape | numpy broadcast of the operand shapes (rank &lt;= 3); scalars are shape () |
| Semantics | b == 0: divide event, result = sign(a)*M (0 if a == 0). \|a\| >= \|b\|: overflow, result = sign(a)*sign(b)*M. Else result = trunc_toward_zero(a * 2^(N-1) / b). |
| Events | divide, overflow |
| Memory | none |
| Predication | events |
| Hardware | NOT SUPPORTED on v1 (no divider). Device.supported_ops excludes it; the runtime raises SFUnsupportedError. Host pre-flight decides every b == 0 lane before launch. |
| v4.8.1 | **host**: no SF divide or reciprocal on the chip (ISA s5) |
| v4.8.1 cost | - |
| MLIR | sf.div; traits: EventEffect (not Pure), Elementwise, SameOperandsAndResultType |
| From Python | a / b, sf.div(a, b, where=mask) |
| Golden vectors | `spec/golden/div.json` |

**Rewrites:**

- no rewrites; in particular a/b is not a * (1/b) (1/b always overflows)

**Notes:**

- the event check order is divide first, then overflow; a lane with b == 0 reports divide only
- sf.div(where=mask) lowers to a predicated div: masked lanes give 0 and no event

### fma

`%r:sfN = fma %a, %b, %c` · version 1.0

| | |
|---|---|
| Operands | a: sfN, b: sfN, c: sfN |
| Result | sfN |
| Shape | broadcast(a, b, c) |
| Semantics | t = mul(a, b) (truncated, may underflow); result = add(t, c) (may saturate). Bit-identical to add(mul(a, b), c). This is NOT a fused single-rounding fma. |
| Events | overflow, underflow |
| Memory | none |
| Predication | events |
| Hardware | FMA unit |

| v4.8.1 cost | 1 instruction |
| MLIR | sf.fma; traits: EventEffect (not Pure), Elementwise, SameOperandsAndResultType |
| From Python | sf.fma(a, b, c), a * b + c |
| Golden vectors | `spec/golden/fma.json` |

- add(mul(a,b),c) &lt;-> fma(a,b,c) is legal both ways (same bits)

**Notes:**

- on v4.8.1 hardware (wide accumulator, single rounding) this would change: major version bump

### narrow

`%r:sfM = narrow %a {bits}` · version 1.0

| | |
|---|---|
| Operands | a: sfN, N > M |
| Attributes | bits: target width M |
| Result | sfM |
| Shape | a |
| Semantics | q = round_half_to_even(a / 2^(N-M)) (floor divmod, then round up if remainder > half, or == half and q odd). If \|q\| > M_max: overflow, clip to +-M_max. underflow if a != 0 and result == 0. |
| Events | overflow, underflow |
| Memory | none |
| Predication | events |
| Hardware | v4.8.1: no conversion instruction; the only hardware rounding is POP on MX results (ISA section 5). Expand or do it on the host |
| v4.8.1 | **none**: no conversion or rounding instruction on FMA / ACT (ISA s5); the only hardware rounding is POP. Run it on the host, or produce sfN directly from MX with POP at N bits |
| v4.8.1 cost | - |
| MLIR | sf.cast (narrowing); traits: EventEffect (not Pure), Elementwise |
| From Python | sf.cast(x, narrower), x.astype(narrower) |
| Golden vectors | `spec/golden/narrow.json` |

**Notes:**

- this is the ONLY op that rounds to nearest. All arithmetic truncates toward zero.
- on sign-magnitude registers: round the magnitude half to even, then keep the sign. This gives the same result as rounding k, because round half to even is symmetric. A result of 0 must be +0.

## Reductions

### sum

`%r:sfN = sum %x {axis}` · version 1.0

| | |
|---|---|
| Operands | x: sfN |
| Attributes | axis: int or None (None = all) |
| Result | sfN |
| Shape | x.shape with axis removed (() for None) |
| Semantics | acc = 0; for i = 0 .. n-1 in index order: acc = add(acc, x[i]) (saturating each step). Overflow if any step saturated. Saturation is sticky in the sense that later steps continue from +-M. |
| Events | overflow |
| Memory | none |
| Predication | events |
| Hardware | ACT chain, sequential |
| v4.8.1 | **expand**: an ACT f=00 chain in index order (order matters: it saturates). Across threads (suggested): each thread STRs its value to the scratchpad, then the chain LDRs them in order |
| v4.8.1 cost | 1 ACT per element, plus scratchpad traffic |
| MLIR | sf.reduce_sum; traits: EventEffect (not Pure) |
| From Python | sf.sum(x, axis), x.sum() |
| Golden vectors | `spec/golden/sum.json` |

**Rewrites:**

- NOT associative: (a+b)+c != a+(b+c) when an intermediate saturates. Do not reassociate, do not reorder a chain, do not tree-reduce.
- result DEPENDS on order: [M, 1, -1] gives M-1, [1, -1, M] gives M

## Contraction

### dot

`%r:sfN[m,n] = dot %a, %b` · version 1.0

| | |
|---|---|
| Operands | a: sfN[m, k], b: sfN[k, n] |
| Result | sfN |
| Shape | (m, n) |
| Semantics | For each (i, j): acc = 0; for t = 0 .. k-1: acc = fma(a[i,t], b[t,j], acc). Every product truncated, every add saturated, at width N, in increasing t. |
| Events | overflow, underflow |
| Memory | none |
| Predication | events |
| Hardware | v4.8.1: a chain of FMA instructions (Rd = accumulator in and out), k in increasing order. Not MX: MX gives different bits (see dot_wide) |
| v4.8.1 | **expand**: (suggested) per output, an FMA chain in increasing k: FMA acc, a[k], b[k] (LDR the operands first). Never MX: MX gives different bits (ISA s3.4 rule 5) |
| v4.8.1 cost | per output: K FMA plus 2K loads |
| MLIR | sf.matmul (linalg.matmul with sf semantics); traits: EventEffect (not Pure) |
| From Python | sf.dot(a, b) in a kernel, a @ b, sf.matmul, sf.addmm (accumulate="chain", the default) |
| Golden vectors | `spec/golden/dot.json` |

**Rewrites:**

- k must be accumulated in increasing order. Tiling over m and n is free; tiling over k is legal ONLY if the partial sum of tile 1 is fed as the initial acc of tile 2 (no separate partials added later)
- split-k, tree reduction, and wider accumulators are NOT legal

**Notes:**

- sf.addmm(a, b, d) is NOT dot with the accumulator starting at d. It is the dot chain from 0, then ONE saturating add of d: add(dot(a, b), d). The two differ when a partial sum saturates.

### dot_wide

`%r:sfN[m,n] = dot_wide %a, %b {shift}` · version 1.1

| | |
|---|---|
| Operands | a: sfN[m, k], b: sfN[k, n] |
| Attributes | shift: int from -32 to 31: the result is the total times 2^shift (POP's s) |
| Result | sfN |
| Shape | (m, n) |
| Semantics | The v4.8.1 MX engine. Block: sf9..sf16 use the SF16 block (accumulator W = 25 bits, F = 19 fraction bits); sf4..sf8 use the SF8 block (W = 20, F = 14). Operands are sign-magnitude, left-aligned in 16 bits; am, bm are the magnitudes the block reads (15 bits, or the 7 bits of the top byte on SF8). Product magnitude: SF16 t = (1024 + sum over set bits i of am of ((bm &lt;&lt; i) & ~511)) >> 11, so NOT exact; SF8 t = am * bm, exact. Sign = sign(a) xor sign(b). For each (i, j): acc = 0; for k0 = 0, 8, 16, ...: acc = saturate_W(acc + sum of the signed t for k in k0 .. k0+7) (two's complement, about +-32). Result (POP): q = round_half_to_even(\|acc\| * 2^(shift - F + N - 1)), clamped to M, with the sign of acc; never -0. |
| Events | overflow, underflow |
| Memory | none |
| Predication | events |
| Hardware | v4.8.1 MX engine, one per tile (ISA section 3.4): CFG (block, N) from thread 0, CLR; per chunk of 8 k: WL rows 7..0 then SWAP; MAC per token into slot t (up to 8 tokens per weight tile); then POP with Rs(c) = t &lt;&lt; 8 \| (shift & 63). 8 output columns per weight tile, 64 MACs per instruction. The engine has no flags. |
| v4.8.1 | **expand**: the MX sequence of ISA s3.4: CFG (block and N, from thread 0) and CLR; per chunk of 8 k: WL rows 7..0 then SWAP; MAC per token into its slot (up to 8 tokens per weight tile); then POP with Rs(c) = slot &lt;&lt; 8 \| (shift & 63). Thread j supplies lane or column j. 8 output columns per weight tile. Weights are not reset at block start: always load all 8 rows and SWAP |
| v4.8.1 cost | 8 WL + 1 SWAP + 1 MAC per token per chunk of 8 k, then 1 POP per token |
| MLIR | sf.matmul_wide &#123;shift&#125;; traits: EventEffect (not Pure) |
| From Python | sf.dot(a, b, accumulate="wide", shift=s) in a kernel, a @ b in a kernel traced under sf.accumulate("wide"), sf.matmul / sf.dot / sf.addmm (accumulate="wide") on host and device arrays |
| Golden vectors | `spec/golden/dot_wide.json` |

**Rewrites:**

- dot_wide never equals dot: never rewrite one into the other, and never fuse an FMA chain into MX
- tiling over m and n is free
- tiling over k is legal only by MACing every chunk into the SAME accumulator slot and doing ONE POP at the end; separate POPs added together round twice and are NOT equivalent
- chunk boundaries are at k = 0, 8, 16, ... (saturation happens once per chunk); pad a short last chunk with zeros, which add nothing
- inside a chunk the order of k does not matter (the 8 products are summed exactly)

**Notes:**

- overflow means the accumulator clipped at +-32 or the POP result clamped at +-M; underflow means a nonzero acc rounded to 0
- on the SF16 block a product below the engine's resolution (e.g. 2^-15 x 2^-15) adds 0, so a total of exactly 0 raises nothing
- golden vectors: spec/golden/dot_wide.json, computed by the chip repo's mxref.Engine (sha256 in the file)
- the kernel trace picks dot or dot_wide from sf.accumulate at trace time; the kernel cache keys on it

### store

`store %ptr, %offs, %val, %mask` · version 1.0

| | |
|---|---|

| Result | none |
| Shape | lanes = broadcast(offs, val, mask) |
