```python
import sf.torch as sft

model = sft.convert(model, dtype=sf.sf16)             # Linear, Conv2d and Hugging Face Conv1D now compute in sf16
fast = torch.compile(model, backend="superfloat")      # sends the SF layers to the device
out = fast(x)
sft.last_status(model)                                 # per-layer saturation report
```

Weights and activations are scaled so the chip's -1..1 range is used well,
and by default the scale leaves enough headroom that nothing can saturate
inside a layer. Training still works (straight-through gradients).

## Wide mode

**For LLMs, run the layers on the MX engine: `accumulate="wide"`.** The default chain clips every partial sum at ±1, so wide layers (K in the thousands) lose their inputs to headroom. Wide mode adds in a wide accumulator and rounds once.

```python
model = sft.convert(model, dtype="sf16", accumulate="wide")
out = model(x)
```

You choose no shifts and give no calibration data. For every call, `sft`:

1. Scales each token by a power of two (`ea`) and each weight channel by a power of two (`ew`), because the chip can only shift.
2. Picks each output's exponent with a fixed rule: `eo = l2 - h`. Here `l2` is the exponent at which the output can never clip (from the two vectors' L2 norms), and `h = max(0, floor(log2 K) // 2 - 2)`.
3. Sets each POP shift to `ea + ew - eo`, from -32 to 31.
4. Pops again at `l2` any output that came back at ±max. That redo always fits.

The rule has no state, so an output depends only on its inputs. Its numbers live in `sf._heuristic` and are pinned by golden vectors.

| Also works | How |
| --- | --- |
| One layer | `sft.SFLinear(..., accumulate="wide")`, `sft.linear(x, w, b, accumulate="wide")` |
| Two activations | `sft.matmul(a, b, accumulate="wide")`: one exponent per row of `a` and per column of `b` |
| An unmodified model | `with sft.autocast(accumulate="wide"):` |
| The chip | `torch.compile(model, backend="superfloat")`: wide layers run on the target's MX engine, with the same bits as on the host |
| A fixed shift | `accumulate="wide", shift=-4` uses that shift for every output, with no redo |

**Read the status, because a wrong shift raises no error.** `sft.last_status(model)` gives each layer's `shift_min`, `shift_max`, `h`, `redone` (outputs popped again), `flushed` (nonzero totals that rounded to 0, unknown on the chip) and `acc_clipped` (always 0: before launch, `sft` raises a token's exponent if its total could reach the accumulator's ±512, and counts it in `guard_raised`).

**sf8 layers, sf16 head.** `sft.convert(model, dtype="sf8", accumulate="wide")` runs the layers at sf8 but keeps the LM head at sf16 by itself, because an sf8 head costs accuracy for little speed. The head is found from the model, not from names:

1. The model's own `get_output_embeddings()` (Hugging Face models).
2. Otherwise a linear layer whose weight is tied to an `nn.Embedding`.
3. Otherwise the last linear layer whose output size is an embedding's vocabulary.

A model with no embedding (a classifier) has no LM head, so nothing is kept. `sft.conversion_report(model).kept_sf16` lists what was kept and why. `keep_sf16=False` turns this off; `keep_sf16=["fc"]` keeps exactly the layers you name.

**Attention runs on MX too.** With `accumulate="wide"`, `sft.convert` and `sft.autocast` catch the model's `F.scaled_dot_product_attention` calls; most Hugging Face LLMs use it. Both matmuls run on the MX engine at sf16, whatever the layers' dtype:

1. Scores `Q Kᵀ`: one exponent per query row and per key, output exponents from the rule above.
2. Mask and softmax: in float on the host, like LayerNorm.
3. `P V`: one exponent per key of V, written once like a KV cache entry. Each row folds its keys' exponents into P exactly (a power of two) and takes the output exponent from the exact bound over the keys it can see, so nothing can saturate and keys appended after a row never change it (DSL 0.16).

Each call is reported as `attention.0.scores` and `attention.0.pv`, then `attention.1...`, in the order the forward makes them. `attention=False` keeps attention in float. Called directly: `sft.attention(q, k, v, attn_mask=None, dropout_p=0.0, is_causal=False, scale=None, enable_gqa=False, name="attention")`.

`nn.MultiheadAttention` is converted too: its four projections become SF linears (`{name}.q`, `.k`, `.v`, `.out`), and in wide mode its attention runs on the MX engine (`{name}.scores`, `.pv`). Same call and returns as PyTorch, including `batch_first`, masks, `key_padding_mask`, `need_weights` and separate `kdim` / `vdim`. Layers with `bias_k` / `bias_v` or `add_zero_attn` stay in float, and the report says why.

**Attention written with `torch.matmul`.** Some models do not call SDPA: Hugging Face models loaded with `attn_implementation="eager"`, Gemma 2 (logit soft-capping) and older code. In wide mode `sft.convert` watches every attention module (a class whose name ends in `Attention`): while it runs, each `torch.matmul` between two activations goes to the MX engine at sf16, and the one after a softmax runs as `P V` (V's exponent per key, as above). A rotary-embedding module inside it stays in float (its angles need float). Statuses: `{module}.scores` and `{module}.pv`.

**Softmax, GELU and SiLU on the chip's integer definitions.** `nonlinear="integer"` runs them through `sf.intops` instead of float on the host: attention's softmax (wide mode), GPT-2's tanh GELU and SiLU (MoE experts' activations too). GELU with erf has no integer form and stays float; LayerNorm and RMSNorm always stay on the host. `ConversionReport.nonlinear` lists what changed.

```python
fast = sft.convert(model, "sf16", accumulate="wide", nonlinear="integer")
```

P·V's exponents come only from the keys a row can see (P ≠ 0): V is quantized per key and the row's P carries its keys' exponents, so a causal row's result does not depend on the keys after it (prefill and decode with a growing KV cache give the same bits), and P·V is never redone. Measured on GPT-2 and Qwen2.5-0.5B, perplexity is unchanged against per-channel V.

The scores enter the integer softmax with their row max subtracted. Quantizing raw scores would saturate Qwen2.5-0.5B's, which reach 1728 on its first token, and double its perplexity.

| WikiText-2, 2,040 tokens | float ops | integer softmax / GELU / SiLU |
| --- | --- | --- |
| GPT-2, matmuls in float | 49.538 | 49.551 |
| GPT-2, matmuls at sf16 (wide) | 49.530 | 49.545 |
| Qwen2.5-0.5B, matmuls in float | 22.415 | 22.418 |
| Qwen2.5-0.5B, matmuls at sf16 (wide) | 22.416 | 22.418 |

**A width per layer.** sf8 everywhere costs Qwen2.5-0.5B about 10% perplexity, but most of it comes from a few layers. Measure each layer's cost in accuracy once, then let the chip's cost table pick the widths:

```python
import math

def evaluate(m):                      # any loss, lower is better: here mean NLL per token on a few windows
    ...

sens = sft.layer_sensitivity(model, evaluate, "sf8")               # one evaluation per layer
plan = sft.fit_widths(model, evaluate, sens, max_loss=math.log(1.02), widths=(8, 16), keep_sf16=False)
print(plan)
fast = sft.convert(model, "sf8", accumulate="wide", **plan.convert_kwargs())
```

`choose_widths` starts every layer at the narrowest width and widens the layer that saves the most loss per unit of cost until the summed loss fits the budget. The cost per MAC comes from `sft.cost_table()` (Alosh's table for chip v4.9.2: energy at 130 nm or 2 nm, cycles or bus words, prefill or decode), read as given. The sum of single-layer losses is only an estimate (on Qwen it was off by up to 1.5x either way), so `fit_widths` measures each plan on the whole model and corrects the budget. Pass `fresh=` (a function that loads the model) to keep one model in memory.

Measured on Qwen2.5-0.5B (WikiText-2, 2,040 tokens, energy at 130 nm):

| Plan | Perplexity | MACs at sf8 | Energy vs all sf16 |
| --- | --- | --- | --- |
| all sf16 | +0.01% | 0% | 100% |
| all sf8, LM head at sf16 (`keep_sf16="auto"`) | +10.4% | 72% | 60% |
| `fit_widths`, budget +2%, sf8 / sf16 | +1.78% | 65% | 64% |

Alosh's configuration chooser (`sft.plan_configs(model, tokens=1, model="llm")`, the rules of the v4.9.2 golden file) puts every layer at sf12 and the LM head at sf16: +0.99%, at 88% of all-sf16 decode cycles. The plans below measure each layer instead.

Chosen for cycles instead (prefill, weights packed, `metric="cycles"`, `widths=(8, 10, 12, 16)`), the same +2% budget gives +1.22% with 56% of MACs at sf8, 37% at sf10 (the LM head among them), 4% at sf12 and 3% at sf16: 81% of all-sf16 cycles, against 77% for all sf8.

The LM head is 27% of Qwen's MACs and costs 1.5% at sf8 but nothing measurable at sf10, so with `widths=(8, 10, 12, 16)` the chooser puts it at sf10. On the v0 table sf9 to sf15 save little energy over sf16 (sf10 is 77% of sf16's energy per MAC, sf8 45%), but packed even widths save cycles.

**MoE models.** Hugging Face keeps every expert of an MoE block in one 3-D parameter (`gate_up_proj`, `down_proj`) and multiplies with a grouped matmul, so there is no `nn.Linear` to swap. `sft.convert` runs those experts itself, one SF linear per expert and projection, with the model's own layout (gate and up concatenated or interleaved, transposed weights, biases, its own gate function). Mixtral, Qwen2-MoE, Qwen3-MoE, DeepSeek-V3 and gpt-oss are covered.

- The experts run at `dtype`; the router (which picks the experts) runs at sf16, like the LM head, and is listed in `kept_sf16`.
- Statuses per expert: `{experts}.gate_up_proj[3]`, `{experts}.down_proj[3]`.
- Under `torch.compile`, each expert runs on every token, multiplied by that token's routing weight (0 where it was not routed). This way no shape depends on the routing, and every projection goes to the target. Each token's row is computed on its own, so the bits are the same as the eager loop; it costs `num_experts / top_k` times the host time.
- The parameters and the state dict keys do not change.

**Weights in other formats.** A weight that is not float is never read as if it were:

| Weight | What `sft.convert` does |
| --- | --- |
| FP8 with scales per block or per tensor (`weight_scale_inv`, DeepSeek-V3 style, `transformers`' `FP8Linear`) | Dequantizes it (each block times its scale), then converts it like any float weight |
| MXFP4 (`nn.Linear` with packed E2M1 weights and an E8M0 scale per block of 32) | Dequantizes it exactly, then converts it like any float weight |
| int8, packed 4-bit, GPTQ / AWQ `qweight`, NVFP4 | Skips it with the reason; the layer runs as it was |
| A subclass of `nn.Linear` with its own `forward` | Skips it: sf cannot tell what it computes from the weight alone |

**gpt-oss and other MXFP4 checkpoints.** The gpt-oss checkpoints keep their experts in MXFP4: `<name>_blocks` (two E2M1 values per byte) and `<name>_scales` (E8M0). Load them into a float model, then convert:

```python
model = AutoModelForCausalLM.from_config(config)          # float skeleton, no quantization_config
model.load_state_dict(other_tensors, strict=False)        # everything that is not MXFP4
sft.load_mxfp4(model, "path/to/checkpoint")               # every *_blocks / *_scales pair, exactly
model = sft.convert(model, dtype="sf16", accumulate="wide")
```

`sft.load_mxfp4` gives the values `transformers` gives when it dequantizes, bit for bit (gpt-oss stores experts as (E, out, in) and they are transposed, as `transformers` does). Loading with `transformers` and `Mxfp4Config(dequantize=True)` reaches the same weights. `sft.dequantize_mxfp4(blocks, scales)` and `sft.quantize_mxfp4(w)` are the decoder and encoder (OCP Microscaling v1.0: nearest E2M1, ties to even, saturating at ±6; shared exponent floor(log2 max) − 2). A module packed for GPU kernels (`Mxfp4GptOssExperts`) is skipped with a pointer to these.

**The report covers every weight.** Besides converted and skipped layers, `sft.conversion_report(model)` lists any module that holds a 2-D (or larger) weight no rule converted, so nothing runs in float without a line saying so. Embedding tables are lookups, not matmuls, and are not listed. `widths` gives each converted module's width, and the first line counts them (`widths: sf8 x 96, sf16 x 25`).

**Speed on the host.** Wide mode emulates the chip bit for bit, which costs time on a CPU. sf compiles a small C accumulator the first time it is used (with `cc`, `gcc` or `clang`), keeps it in a private per-user cache folder (`~/.cache/sf`, or `$SF_CACHE_DIR`), and splits rows across cores; GPT-2 small runs about 30 times faster than the plain NumPy model, with the same bits. With no C compiler sf uses the NumPy model; `SF_FAST_MX=0` forces it.

**Weights are prepared once.** On the first call of each wide layer, sf quantizes its weight per channel and keeps it in a compact form (3 bytes per weight) with its norms; later calls reuse it, so a chat model spends its time on the chip arithmetic, not on preparing weights. Qwen2.5-0.5B: about 1 second per generated token instead of 20, with identical outputs. A weight changed in place (a training step) is prepared again. The cache holds up to `SF_WEIGHT_CACHE_MB` (default 4096); `0` turns it off. To try it: `python examples/chat_wide.py`.

- In wide mode `scale=` and `headroom=` are not used: weights are always per channel, and partial sums cannot clip at ±1.
- The bias is added on the chip after POP, in SF arithmetic: quantized to each output's exponent and added with the saturating add (one `ACT` per output). An output whose sum reaches the limit, or whose bias did not fit that exponent, is recomputed at a larger exponent; `bias_saturated` in the layer status counts any bias that still did not fit.
- A target without an MX engine keeps wide layers on the host, and `sft.compile_report()` says so.
